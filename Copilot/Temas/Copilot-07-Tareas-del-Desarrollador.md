# Topic 07 — Refactoring, documentation, testing and debugging with GitHub Copilot

## 1. Introduction

In previous topics we've seen how to set up GitHub Copilot, how to write better prompts, and how to use Copilot Chat to chat about code.  
In this topic we are going to use Copilot in common tasks of daily development work:

- refactor code;
- document functions, classes and files;
- generate tests;
- analyze errors;
- detect possible bugs;
- review code before integrating it into a project.

GitHub Copilot can greatly speed up these tasks, but should not be used as a substitute for technical judgment. The developer remains responsible for understanding, reviewing, testing, and maintaining the code.

> **Key idea:** Copilot helps propose solutions, but does not guarantee that those solutions are correct, safe, efficient, or consistent with the project.

---

## 2. Objectives of the topic

By the end of this topic you should be able to:

- Use Copilot to improve the readability of a code snippet.
- Request specific refactorings without changing the behavior of the program.
- Generate useful and not excessive documentation.
- Create unit tests from an existing function.
- Ask Copilot to explain an error or trace.
- Use Copilot as support in debugging tasks.
- Critically review the responses generated by Copilot.
- Apply a basic code review checklist generated with AI.

---

## 3. Before you start

To follow this topic it is advisable to have:

- GitHub Copilot activated.
- VS Code or a Copilot compatible IDE.
- A small JavaScript, TypeScript, Python, Java or other language project.
- Basic knowledge of functions, conditions, arrays/lists and tests.

In the examples of this topic we will mainly use JavaScript because it allows us to see the concepts in a simple way.  
The same logic can be applied to other languages.

# Part 1. Refactoring with GitHub Copilot

## 4. What does it mean to refactor

Refactoring means **improving the internal structure of the code without changing its external behavior**.

It is not about adding new features.  
It is not about changing what the program does.  
It consists of making the code clearer, maintainable, reusable or easier to test.

Refactoring examples:

- Change unclear variable names.
- Extract repeated logic to a function.
- Split a function that is too long.
- Reduce nested conditions.
- Separate responsibilities.
- Eliminate duplications.
- Improve file organization.

---

## 5. When to request a refactoring from Copilot

You can ask Copilot for help when you find code like this:

```js
function p(a, b, c) {
  let x = 0;

  for (let i = 0; i < a.length; i++) {
    if (a[i].active === true) {
      if (a[i].type === b) {
        x = x + a[i].price;
      }
    }
  }

  if (c === true) {
    x = x - x * 0.1;
  }

  return x;
}
```

This code works, but has several problems:

- Variable names do not explain what they represent.
- There are nested conditions.
- It is not clear what `c` means.
- The discount operation is mixed with the calculation of the total.
- The function does several things at the same time.

---

## 6. How to request a refactoring correctly

A too general prompt would be:

```text
Refactoriza este código.
```

This prompt may work, but it is not very precise. Copilot doesn't know what type of refactoring you want or what it should keep.

A better prompt would be:

```text
Refactoriza esta función para mejorar la legibilidad, pero sin cambiar su comportamiento.
Usa nombres de variables más descriptivos, reduce las condiciones anidadas y separa el cálculo del descuento en una función auxiliar.
No cambies la firma de la función original.
```

Notice that the second prompt indicates:

- what you want to improve;
- what should not be changed;
- what kind of result is expected;
- what restriction must be respected.

---

## 7. Step by Step Guide: Refactor a Function with Copilot

### Step 1. Select the code

Select the function you want to improve in the editor.

### Step 2. Open Copilot Chat

Open Copilot Chat in the IDE.

In VS Code, you can usually open it from:

- the Copilot icon;
- the side panel;
- the context menu;
- a keyboard shortcut, depending on your settings.

### Step 3. Write a specific prompt

Example:

```text
Refactoriza el código seleccionado para mejorar su legibilidad.
Mantén exactamente el mismo comportamiento.
No añadas nuevas dependencias.
Explica brevemente qué cambios has hecho.
```

### Step 4. Read the proposal

Don't automatically accept the result. Check:

- if the logic holds;
- if the names are clear;
- if no important validation has been removed;
- if no unnecessary code has been added;
- whether the style fits with the rest of the project.

### Step 5. Apply the changes in a controlled manner

If the IDE allows you to apply the hint automatically, check the diff before accepting.

### Step 6. Run the project or tests

After refactoring, run the tests or manually test the functionality.

---

## 8. Refactoring example

Initial code:

```js
function p(a, b, c) {
  let x = 0;

  for (let i = 0; i < a.length; i++) {
    if (a[i].active === true) {
      if (a[i].type === b) {
        x = x + a[i].price;
      }
    }
  }

  if (c === true) {
    x = x - x * 0.1;
  }

  return x;
}
```

Recommended Prompt:

```text
Refactoriza esta función de JavaScript para que sea más legible.
Mantén el mismo comportamiento.
Usa nombres de variables claros.
Extrae la lógica del descuento a una función auxiliar.
No añadas librerías externas.
```

A possible answer would be:

```js
function calculateTotalByType(products, selectedType, applyDiscount) {
  let total = 0;

  for (const product of products) {
    const isValidProduct =
      product.active === true && product.type === selectedType;

    if (isValidProduct) {
      total += product.price;
    }
  }

  return applyDiscount ? applyTenPercentDiscount(total) : total;
}

function applyTenPercentDiscount(total) {
  return total - total * 0.1;
}
```

The code is clearer because:

- `products` is more descriptive than `a`;
- `selectedType` is more descriptive than `b`;
- `applyDiscount` is more descriptive than `c`;
- nesting has been reduced;
- the discount is separated into another function.

---

## 9. Important caution when refactoring

Copilot can change the behavior of the code without making it obvious.

For example, you could transform this:

```js
if (product.active === true)
```

in this:

```js
if (product.active)
```

In many cases it will be equivalent, but not always.  
If `active` could have values ​​like `"yes"`, `1`, `null`, or `undefined`, the behavior might change.

Therefore, after a refactoring, you should always check:

- normal inputs;
- limit entries;
- null values;
- unexpected values;
- error cases.

# Part 2. Documentation with GitHub Copilot

## 10. What documentation can Copilot generate

Copilot can help create:

- short comments;
- function documentation;
- class documentation;
- component documentation;
- `README.md` files;
- examples of use;
- parameter tables;
- installation instructions;
- API documentation;
- contribution guides.

However, documenting does not mean filling the code with comments.  
Good documentation should clarify what is not obvious.

---

## 11. Helpful Comments vs. Unnecessary Comments

Unnecessary comment:

```js
// Suma 1 a counter
counter++;
```

This comment doesn't contribute anything because the code already says so.

Helpful comment:

```js
// Se aplica un descuento fijo porque la promoción se calcula antes de impuestos.
const finalPrice = applyDiscount(basePrice);
```

This comment explains a business decision that cannot be deduced from the code alone.

---

## 12. Step by Step Guide: Document a Function
We start from this function:

```js
function calculateFinalPrice(price, discountPercentage, taxPercentage) {
  const discountedPrice = price - price * (discountPercentage / 100);
  return discountedPrice + discountedPrice * (taxPercentage / 100);
}
```

### Step 1. Select the function

Select the full function.

### Step 2. Request specific documentation

Prompt:

```text
Documenta esta función usando JSDoc.
Incluye descripción, parámetros, valor de retorno y un ejemplo breve de uso.
No cambies el código de la función.
```

### Step 3. Review the generated documentation

A possible way out would be:

```js
/**
 * Calculates the final price after applying a discount and then adding tax.
 *
 * @param {number} price - Original price before discount and tax.
 * @param {number} discountPercentage - Discount percentage to apply.
 * @param {number} taxPercentage - Tax percentage to apply after the discount.
 * @returns {number} Final price after discount and tax.
 *
 * @example
 * calculateFinalPrice(100, 10, 21); // 108.9
 */
function calculateFinalPrice(price, discountPercentage, taxPercentage) {
  const discountedPrice = price - price * (discountPercentage / 100);
  return discountedPrice + discountedPrice * (taxPercentage / 100);
}
```

### Step 4. Check that the example is correct

Don't assume that the example generated by Copilot is correct.  
Check manually:

- Starting price: 100.
- 10% discount: 100 - 10 = 90.
- 21% tax on 90: 18.9.
- Final price: 108.9.

The example is correct.

# Part 3. Testing with GitHub Copilot

## 14. What Copilot can do with tests

Copilot can help:

- generate unit tests;
- suggest borderline cases;
- create mocks;
- detect uncovered cases;
- update tests after a change;
- explain why a test fails;
- propose clearer test names;
- improve the structure of a test file.

But Copilot doesn't automatically know all the business requirements.  
Therefore, the generated tests must be carefully reviewed.

---

## 15. What is a good test

A good test should:

- check a specific behavior;
- have a clear name;
- be easy to read;
- do not depend on other tests;
- include normal cases and borderline cases;
- fail if the expected behavior is broken.

Function example:

```js
function isAdult(age) {
  return age >= 18;
}

module.exports = { isAdult };
```

Basic test with Jest:

```js
const { isAdult } = require("./isAdult");

test("returns true when age is 18 or greater", () => {
  expect(isAdult(18)).toBe(true);
  expect(isAdult(25)).toBe(true);
});

test("returns false when age is lower than 18", () => {
  expect(isAdult(17)).toBe(false);
});
```

---

## 16. Step-by-step guide: order unit tests from Copilot

### Step 1. Select the function

Select the function you want to test.

### Step 2. Indicate the testing framework

Copilot needs to know if you use Jest, Vitest, JUnit, Pytest, NUnit, etc.

Prompt:

```text
Genera tests unitarios para esta función usando Jest.
Incluye casos normales, casos límite y casos de error.
No cambies la función original.
```

### Step 3. Review the proposed cases

Check if the tests cover:

- expected values;
- minimum values;
- maximum values;
- null values;
- empty values;
- errors;
- behavior not permitted.

### Step 4. Run the tests

If you work with Node.js and Jest, you can usually run:

```bash
npm test
```

or:

```bash
npx jest
```

### Step 5. Correct the tests if necessary

If Copilot has generated incorrect tests, you can ask it:

```text
Estos tests fallan porque la función no lanza errores con valores nulos.
Corrige los tests para que reflejen el comportamiento real de la función.
```

---

## 17. Complete testing example

Function:

```js
function calculateDiscountedPrice(price, discountPercentage) {
  if (price < 0) {
    throw new Error("Price cannot be negative");
  }

  if (discountPercentage < 0 || discountPercentage > 100) {
    throw new Error("Discount percentage must be between 0 and 100");
  }

  return price - price * (discountPercentage / 100);
}

module.exports = { calculateDiscountedPrice };
```

Prompt:

```text
Genera tests unitarios para esta función usando Jest.
Incluye:
- un caso sin descuento;
- un caso con descuento;
- un caso con descuento del 100%;
- un caso con precio negativo;
- un caso con descuento menor que 0;
- un caso con descuento mayor que 100.
```

Possible output:

```js
const { calculateDiscountedPrice } = require("./calculateDiscountedPrice");

describe("calculateDiscountedPrice", () => {
  test("returns the same price when discount is 0", () => {
    expect(calculateDiscountedPrice(100, 0)).toBe(100);
  });

  test("applies the discount correctly", () => {
    expect(calculateDiscountedPrice(100, 20)).toBe(80);
  });

  test("returns 0 when discount is 100", () => {
    expect(calculateDiscountedPrice(100, 100)).toBe(0);
  });

  test("throws an error when price is negative", () => {
    expect(() => calculateDiscountedPrice(-10, 20)).toThrow(
      "Price cannot be negative",
    );
  });

  test("throws an error when discount is lower than 0", () => {
    expect(() => calculateDiscountedPrice(100, -1)).toThrow(
      "Discount percentage must be between 0 and 100",
    );
  });

  test("throws an error when discount is greater than 100", () => {
    expect(() => calculateDiscountedPrice(100, 101)).toThrow(
      "Discount percentage must be between 0 and 100",
    );
  });
});
```

---

## 18. How to order better tests

A weak prompt would be:

```text
Haz tests.
```

A better prompt would be:

```text
Genera tests unitarios con Jest para esta función.
Quiero que cubras casos normales, casos límite y errores.
Usa nombres de test descriptivos.
No modifiques la función original.
Después, indícame qué casos quedan sin cubrir.
```

You can also ask for:

```text
Analiza estos tests y dime si falta algún caso importante.
No escribas código todavía. Primero explícame qué cobertura lógica tienen.
```

This approach is useful because it forces Copilot to reason before generating more code.

# Part 4. Debugging with GitHub Copilot

## 19. What is AI assisted debugging

Debugging means finding and fixing errors in a program.

Copilot can help:

- explain an error trace;
- locate a possible cause;
- propose hypotheses;
- suggest logs;
- review conditions;
- detect unexpected values;
- propose changes;
- explain why a test fails.

But Copilot doesn't mentally run the program as reliably as a real debugger.  
Debugging must combine AI, reading the code, logs, tests and actual execution.
---

## 20. Step-by-step guide: analyze an error with Copilot

### Step 1. Copy the entire error

Don't just paste the last line.  
Includes:

- error message;
- stack trace;
- archive;
- line;
- command executed;
- minimal code context.

### Step 2. Ask for an explanation before asking for a solution

Recommended Prompt:

```text
Explícame este error paso a paso.
No propongas todavía una solución.
Primero dime cuál parece ser la causa más probable y qué información adicional habría que comprobar.
```

### Step 3. Ask for a hypothesis

```text
Dame tres posibles causas de este error, ordenadas de más probable a menos probable.
Indica cómo comprobaría cada una.
```

### Step 4. Request a minimum correction

```text
Propón la corrección mínima para resolver este error.
No refactorices el resto del archivo.
Explica por qué el cambio debería funcionar.
```

### Step 5. Test the solution

Run the failed command again.

### Step 6. Confirm that you have not entered another error

Run the tests or manually test the affected functionality.

---

## 21. Error example

Code:

```js
function getUserName(user) {
  return user.profile.name.toUpperCase();
}

console.log(getUserName({ profile: null }));
```

Error:

```text
TypeError: Cannot read properties of null (reading 'name')
```

Prompt:

```text
Explícame por qué aparece este error en el código seleccionado.
Después propón una corrección mínima y otra corrección más robusta.
```

Possible explanation:

- `user.profile` is `null`.
- The code tries to access `user.profile.name`.
- Cannot read property `name` of `null`.

Minimum correction:

```js
function getUserName(user) {
  if (user.profile === null) {
    return "";
  }

  return user.profile.name.toUpperCase();
}
```

More robust fix:

```js
function getUserName(user) {
  return user?.profile?.name?.toUpperCase() ?? "";
}
```

The second version also covers cases such as:

- `user` is `undefined`;
- `profile` does not exist;
- `name` does not exist;
- `name` is `null`.

# Part 5. Bug detection and code review

## 22. Copilot as a code reviewer

Copilot can act as a first reviewer, but is not a substitute for a human code review.

It can help detect:

- incorrect conditions;
- missing validations;
- duplications;
- dead code;
- possible typos;
- security issues;
- borderline cases not contemplated;
- insufficient tests.

---

## 23. Prompt for code review

```text
Revisa el código seleccionado como si fueras un revisor técnico.
Busca:
- posibles bugs;
- casos límite no contemplados;
- problemas de legibilidad;
- duplicación;
- riesgos de seguridad;
- tests que deberían añadirse.

No reescribas el código todavía.
Primero dame una lista priorizada de problemas.
```

This prompt is useful because it first asks for analysis, not a solution.  
Then you can ask:

```text
Ahora aplica solo las correcciones de prioridad alta.
No cambies el estilo general del archivo.
Explica cada cambio realizado.
```

---

## 24. Checklist to review code generated by Copilot

Before accepting code generated by Copilot, check:

- Do I understand all the generated code?
- Does the code really solve the problem?
- Has any part been changed that should not have been changed?
- Are there clear names?
- Are there sufficient validations?
- Are there uncovered borderline cases?
- Have unnecessary dependencies been added?
- Has sensitive information been entered?
- Does the code follow the style of the project?
- Are there tests?
- Do the tests pass?
- Does the documentation match the actual behavior?

---

## 25. Recommended workflow

A good workflow with Copilot would be:

1. **Understand the current code.**
2. **Ask Copilot for an explanation.**
3. **Ask for an improvement proposal.**
4. **Review the proposal.**
5. **Apply changes in a controlled manner.**
6. **Run tests.**
7. **Ask Copilot to review possible edge cases.**
8. **Document important changes.**
9. **Do a final human review.**

---

## 26. Common mistakes when using Copilot in these tasks

### Error 1. Accept code without reading it

Copilot can generate code that looks correct but contains subtle errors.

### Error 2. Asking for changes that are too broad

Problematic prompt:

```text
Mejora todo este proyecto.
```

It is better to divide the task:

```text
Analiza este archivo y dime tres mejoras de legibilidad.
No modifiques todavía el código.
```

### Error 3. Mixing refactoring with new features
If you ask to refactor and add new behavior at the same time, it will be more difficult to detect errors.

### Error 4. Not running tests

A refactoring without tests is risky.

### Error 5. Asking for tests without explaining the business logic

Copilot can generate tests that are technically correct but functionally incomplete.
