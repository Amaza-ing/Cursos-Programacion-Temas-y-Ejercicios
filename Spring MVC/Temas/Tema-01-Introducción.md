## 2. What is Spring MVC?

Spring MVC is the Spring module that allows you to create web applications following the Model-View-Controller pattern.

MVC means:

| Element | Meaning | Responsibility |
| ----------- | ----------- | ---------------------------------------------------------------- |
| Model | Model | Contains the data that we want to display or process |
| View | View | It is the page that the user will see |
| Controller | Controller | Receives the request, prepares the data and decides which view to show |

For example, let's imagine that the user enters this address:

```text
http://localhost:8080/spring-mvc-day1/home
```

Spring MVC must answer several questions:

1. Which driver should serve the `/home` URL?
2. What data does the page need?
3. Which view should be displayed?
4. What final HTML is returned to the browser?

## 3. Spring MVC general architecture

In a Spring MVC application, the user does not directly access JSP pages.

The usual flow is this:

```text
Navegador
   ↓
Petición HTTP
   ↓
DispatcherServlet
   ↓
HandlerMapping
   ↓
Controller
   ↓
ModelAndView
   ↓
ViewResolver
   ↓
Vista JSP
   ↓
Respuesta HTML
```

We are going to explain each part little by little.

---

## 4. The role of `DispatcherServlet`

`DispatcherServlet` is one of the most important elements of Spring MVC.

It is a central servlet that receives HTTP requests and coordinates the rest of the process.

We don't usually write the `DispatcherServlet` code directly. Spring already provides it. What we do is configure it.

When a request arrives, `DispatcherServlet` does something like this:

```text
1. Recibe la petición HTTP.
2. Busca qué controlador debe atender esa petición.
3. Ejecuta el controlador.
4. Recibe el resultado del controlador.
5. Busca qué vista debe mostrarse.
6. Envía la respuesta HTML al navegador.
```

That is why `DispatcherServlet` is said to act as a **front controller**.

A **front controller** is a centralized entry point for requests from a web application.

## 8. Configure Maven with `pom.xml`

The `pom.xml` file is used to configure the Maven project.

In it we indicate:

- The name of the project.
- Java version.
- The dependencies that we are going to use.
- The type of application packaging.

Replace the content of your `pom.xml` with this code:

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="
            http://maven.apache.org/POM/4.0.0
            https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>spring-mvc-day1</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>war</packaging>

    <properties>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <spring.version>6.2.12</spring.version>
    </properties>

    <dependencies>

        <!-- Spring MVC -->
        <dependency>
            <groupId>org.springframework</groupId>
            <artifactId>spring-webmvc</artifactId>
            <version>${spring.version}</version>
        </dependency>

        <!-- Servlet API: la proporciona Tomcat en tiempo de ejecución -->
        <dependency>
            <groupId>jakarta.servlet</groupId>
            <artifactId>jakarta.servlet-api</artifactId>
            <version>6.0.0</version>
            <scope>provided</scope>
        </dependency>

    </dependencies>

    <build>
        <finalName>spring-mvc-day1</finalName>

        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-war-plugin</artifactId>
                <version>3.4.0</version>
            </plugin>
        </plugins>
    </build>

</project>
```

### `pom.xml` Explanation

This part identifies the project:

```xml
<groupId>com.example</groupId>
<artifactId>spring-mvc-day1</artifactId>
<version>1.0-SNAPSHOT</version>
```

`groupId` usually represents the base organization or package of the project.

`artifactId` is the name of the project.

`version` indicates the current version of the project.

---

This line is very important:

```xml
<packaging>war</packaging>
```

With this we indicate that we want to create a web application packaged as an `.war` file.

An `.war` file is the typical format for Java web applications that are deployed on servers such as Tomcat.

---

Then we indicate the Java version:

```xml
<maven.compiler.source>17</maven.compiler.source>
<maven.compiler.target>17</maven.compiler.target>
```

We are using Java 17 because Spring Framework 6 requires Java 17 or higher.

---

This property allows us to define the Spring version in one place:

```xml
<spring.version>6.2.12</spring.version>
```

Thus, if later we want to change the Spring version, we will only have to modify this line.

---

The main dependency of the project is this:

```xml
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-webmvc</artifactId>
    <version>${spring.version}</version>
</dependency>
```

This dependency includes the classes necessary to work with Spring MVC.

For example:

- `DispatcherServlet`
- `ModelAndView`
- `ViewResolver`
- Drivers
- URL mappings
- MVC Configuration

---

We also add the Servlet API:

```xml
<dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <version>6.0.0</version>
    <scope>provided</scope>
</dependency>
```

This dependency contains classes necessary to work with HTTP requests and responses.

For example:

```java
HttpServletRequest
HttpServletResponse
```

We use:

```xml
<scope>provided</scope>
```

because Tomcat already provides this library when you run the application.

That is, we need this dependency to compile the project, but it is not necessary to include it within the `.war`.

---

Finally, we configure the final name of the generated file:

```xml
<finalName>spring-mvc-day1</finalName>
```

This will cause the generated `.war` to have this name:

```text
spring-mvc-day1.war
```

## 9. Create `web.xml` file

Now let's configure the web application.

Create this file:

```text
src/main/webapp/WEB-INF/web.xml
```

If the `WEB-INF` folder does not exist, create it manually.

The `web.xml` file is used to configure elements of the web application.

In our case, we will use it to register `DispatcherServlet`.

Complete code:

```xml
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="
            https://jakarta.ee/xml/ns/jakartaee
            https://jakarta.ee/xml/ns/jakartaee/web-app_6_0.xsd"
         version="6.0">

    <display-name>Spring MVC Day 1</display-name>

    <servlet>
        <servlet-name>app</servlet-name>
        <servlet-class>org.springframework.web.servlet.DispatcherServlet</servlet-class>

        <init-param>
            <param-name>contextConfigLocation</param-name>
            <param-value>/WEB-INF/spring/app-servlet.xml</param-value>
        </init-param>

        <load-on-startup>1</load-on-startup>
    </servlet>

    <servlet-mapping>
        <servlet-name>app</servlet-name>
        <url-pattern>/</url-pattern>
    </servlet-mapping>

</web-app>
```

### `web.xml` explanation

This first part indicates that we are using a Jakarta EE based web application:

```xml
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         ...
         version="6.0">
```

This is important because Spring 6 uses `jakarta.*` instead of `javax.*`.

---

Then we give a descriptive name to the application:

```xml
<display-name>Spring MVC Day 1</display-name>
```

This name does not affect the operation of the application, but helps identify it.

---

The most important part is this:

```xml
<servlet>
    <servlet-name>app</servlet-name>
    <servlet-class>org.springframework.web.servlet.DispatcherServlet</servlet-class>
</servlet>
```

Here we are registering a servlet called `app`.

That servlet will be an instance of:

```text
org.springframework.web.servlet.DispatcherServlet
```

That is, we are telling Tomcat:

> This application will use the Spring MVC core servlet.

---

Then we indicate where the Spring MVC configuration file is:

```xml
<init-param>
    <param-name>contextConfigLocation</param-name>
    <param-value>/WEB-INF/spring/app-servlet.xml</param-value>
</init-param>
```

This means that when you boot `DispatcherServlet`, you will need to load its configuration from:

```text
/WEB-INF/spring/app-servlet.xml
```

We have not created that file yet. We will create it in the next step.

---

We also add:

```xml
<load-on-startup>1</load-on-startup>
```

This indicates that `DispatcherServlet` will be loaded when the application starts.

If we didn't put this line, it could be loaded when the first request arrived.

---

Finally, we configure which URLs will go through `DispatcherServlet`:

```xml
<servlet-mapping>
    <servlet-name>app</servlet-name>
    <url-pattern>/</url-pattern>
</servlet-mapping>
```

With this we indicate that the application requests will go through the Spring MVC servlet.

## 10. Create Spring MVC Configuration with XML

Now we are going to create the file that was indicated in `web.xml`.

Create the folder:

```text
src/main/webapp/WEB-INF/spring
```

Inside that folder create the file:

```text
app-servlet.xml
```

The complete route will be:

```text
src/main/webapp/WEB-INF/spring/app-servlet.xml
```

Complete code:

```xml
<?xml version="1.0" encoding="UTF-8"?>

<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:mvc="http://www.springframework.org/schema/mvc"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="
          http://www.springframework.org/schema/beans
          https://www.springframework.org/schema/beans/spring-beans.xsd
          http://www.springframework.org/schema/mvc
          https://www.springframework.org/schema/mvc/spring-mvc.xsd">

    <!-- Controlador registrado manualmente como bean -->
    <bean id="homeController"
          class="com.example.springmvcday1.controller.HomeController" />

    <!-- Mapeo de URLs mediante XML -->
    <bean class="org.springframework.web.servlet.handler.SimpleUrlHandlerMapping">
        <property name="mappings">
            <props>
                <prop key="/">homeController</prop>
                <prop key="/home">homeController</prop>
            </props>
        </property>
    </bean>

    <!-- Resolución de vistas JSP -->
    <bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">
        <property name="prefix" value="/WEB-INF/views/" />
        <property name="suffix" value=".jsp" />
    </bean>

    <!-- Recursos estáticos: CSS, JS, imágenes, etc. -->
    <mvc:resources mapping="/resources/**" location="/resources/" />

</beans>
```

### `app-servlet.xml` Explanation

This file is Spring MVC's own configuration.

Here we indicate:

1. What controller are we going to use.
2. What URL that controller will run.
3. Where are the JSP views.
4. Where are the static resources.

---

First we register a controller as a Spring bean:

```xml
<bean id="homeController"
      class="com.example.springmvcday1.controller.HomeController" />
```

This means:

> Spring must create an object of class `HomeController` and save it with the name `homeController`.

We haven't created the `HomeController` class yet, but we will create it in the next step.

---

Next we configure the URL mappings:

```xml
<bean class="org.springframework.web.servlet.handler.SimpleUrlHandlerMapping">
    <property name="mappings">
        <props>
            <prop key="/">homeController</prop>
            <prop key="/home">homeController</prop>
        </props>
    </property>
</bean>
```

This block connects URLs with controllers.

The configuration says:

| URL | Controller running |
| ------- | -------------------------- |
| `/` | `homeController` |
| `/home` | `homeController` |

Therefore, these two routes will run the same driver:

```text
http://localhost:8080/spring-mvc-day1/
```

```text
http://localhost:8080/spring-mvc-day1/home
```

---

Then we configure the view resolver:

```xml
<bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">
    <property name="prefix" value="/WEB-INF/views/" />
    <property name="suffix" value=".jsp" />
</bean>
```

An `ViewResolver` is used to convert a logical view name to an actual path.

For example, if a controller returns this view:

```java
new ModelAndView("home");
```

Spring will apply the configured prefix and suffix:

```text
/WEB-INF/views/ + home + .jsp
```

The result will be:

```text
/WEB-INF/views/home.jsp
```

So the driver does not need to know the full path of the JSP file.

---

Finally, we configure the static resources:

```xml
<mvc:resources mapping="/resources/**" location="/resources/" />
```

This allows files such as:

-CSS
- JavaScript
- Images

from this folder:

```text
src/main/webapp/resources
```

For example, a file located here:

```text
src/main/webapp/resources/css/styles.css
```

It can be loaded from the browser using a URL similar to this:

```text
/spring-mvc-day1/resources/css/styles.css
```

## 11. Create the `HomeController` driver

Now let's create the controller.

Create the package:

```text
src/main/java/com/example/springmvcday1/controller
```

Inside create the file:

```text
HomeController.java
```

Complete code:

```java
package com.example.springmvcday1.controller;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.web.servlet.ModelAndView;
import org.springframework.web.servlet.mvc.Controller;

public class HomeController implements Controller {

    @Override
    public ModelAndView handleRequest(
            HttpServletRequest request,
            HttpServletResponse response) {

        ModelAndView modelAndView = new ModelAndView("home");

        modelAndView.addObject("pageTitle", "Bienvenida a Spring MVC");
        modelAndView.addObject("message", "Nuestra primera aplicación Spring MVC funciona correctamente.");
        modelAndView.addObject("courseName", "Curso de Spring MVC - Día 1");

        return modelAndView;
    }
}
```

### `HomeController.java` Explanation

The first line indicates the class package:

```java
package com.example.springmvcday1.controller;
```

This must match the folder where we created the file.

---

Then we import Jakarta Servlet classes:

```java
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
```

`HttpServletRequest` represents the HTTP request.

`HttpServletResponse` represents the HTTP response.

In this first example we are not going to use them directly, but they are part of the mandatory method of the classic controller.

---

Then we import Spring MVC classes:

```java
import org.springframework.web.servlet.ModelAndView;
import org.springframework.web.servlet.mvc.Controller;
```

`Controller` is a classic Spring MVC interface.

`ModelAndView` represents two things at once:

1. The model, that is, the data we want to send to the view.
2. The view, that is, the page we want to display.

---

The class implements the `Controller` interface:

```java
public class HomeController implements Controller {
```

This means that `HomeController` will be a Spring MVC handler.

---

The main method is this:

```java
@Override
public ModelAndView handleRequest(
        HttpServletRequest request,
        HttpServletResponse response) {
```

This method is executed when a request reaches this controller.

In our case, it will be executed when the user enters:

```text
/
```

or in:

```text
/home
```

because that's how we have configured it in `app-servlet.xml`.

---

Inside the method we create an `ModelAndView` object:

```java
ModelAndView modelAndView = new ModelAndView("home");
```

Here we are saying that we want to display the view called:

```text
home
```

We are not writing directly:

```text
/WEB-INF/views/home.jsp
```

We just write the logical name of the view.

Spring will complete the actual path using the `ViewResolver`.

---

Then we add data to the model:

```java
modelAndView.addObject("pageTitle", "Bienvenida a Spring MVC");
modelAndView.addObject("message", "Nuestra primera aplicación Spring MVC funciona correctamente.");
modelAndView.addObject("courseName", "Curso de Spring MVC - Día 1");
```

Each call to `addObject` adds data that can then be used in the JSP view.

For example, this data:

```java
modelAndView.addObject("pageTitle", "Bienvenida a Spring MVC");
```

can be displayed in JSP like this:

```jsp
${pageTitle}
```

---

Finally we return the object:

```java
return modelAndView;
```

With this the controller tells Spring MVC:

> Show the `home` view and send this data to it.

## 13. Why do we put views inside `WEB-INF`?

JSP views are inside:

```text
src/main/webapp/WEB-INF/views
```

This is intentional.

Files inside `WEB-INF` cannot be opened directly from the browser.

This means that the user cannot directly enter:

```text
http://localhost:8080/spring-mvc-day1/WEB-INF/views/home.jsp
```

Instead, you should enter:

```text
http://localhost:8080/spring-mvc-day1/home
```

This way we ensure that the views always go through a controller.

This is important because the controller is the one who prepares the data that the view needs.

## 15. Complete App Flow

Now that we have all the files, let's go over what happens when the user enters:

```text
http://localhost:8080/spring-mvc-day1/home
```

### Step 1: The browser sends a request

The browser requests this URL:

```text
GET /spring-mvc-day1/home
```

---

### Step 2: Tomcat receives the request

Tomcat detects that the request belongs to the application:

```text
spring-mvc-day1
```

---

### Step 3: The request enters `DispatcherServlet`

In `web.xml` we have this configuration:

```xml
<servlet-mapping>
    <servlet-name>app</servlet-name>
    <url-pattern>/</url-pattern>
</servlet-mapping>
```

That causes the request to go through `DispatcherServlet`.

---

### Step 4: Spring looks for which driver to run

In `app-servlet.xml` we have this mapping:

```xml
<prop key="/home">homeController</prop>
```

Therefore, Spring knows to execute:

```text
homeController
```

---

### Step 5: `HomeController` is executed

Spring calls the method:

```java
handleRequest(request, response)
```

Within that method you create:

```java
ModelAndView modelAndView = new ModelAndView("home");
```

And data is added to the model:

```java
modelAndView.addObject("pageTitle", "Bienvenida a Spring MVC");
modelAndView.addObject("message", "Nuestra primera aplicación Spring MVC funciona correctamente.");
modelAndView.addObject("courseName", "Curso de Spring MVC - Día 1");
```

---

### Step 6: The driver returns an `ModelAndView`

The controller returns:

```java
return modelAndView;
```

That object contains:

- The logical name of the view: `home`
- The data that the view will be able to display

---

### Step 7: Spring resolves the view

In `app-servlet.xml` we have:

```xml
<property name="prefix" value="/WEB-INF/views/" />
<property name="suffix" value=".jsp" />
```

Spring converts:

```text
home
```

in:

```text
/WEB-INF/views/home.jsp
```

---

### Step 8: The JSP is processed

The JSP receives the data from the model and generates HTML.

For example:

```jsp
${pageTitle}
```

becomes:

```text
Bienvenida a Spring MVC
```

---

### Step 9: Tomcat returns HTML to the browser

The user finally sees an HTML page.

The important thing is that the user has not directly opened `home.jsp`.

The user entered a URL, Spring MVC executed a controller, and then displayed a view.

## 18. Common mistakes and solutions

### Error 1: Using Tomcat 9 with Spring 6

Spring 6 uses Jakarta EE and `jakarta.*` packages.

Tomcat 9 works with older Java EE and `javax.*` packages.

Therefore, for this project you must use Tomcat 10 or higher.

---

### Error 2: import `javax.servlet`

Incorrect for this project:

```java
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
```

Correct:

```java
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
```

---

### Error 3: View does not appear

If you see a 404 error, check that the JSP is exactly here:

```text
src/main/webapp/WEB-INF/views/home.jsp
```

Also check that the controller returns:

```java
new ModelAndView("home");
```

If the driver returns `"home"`, Spring will look for:

```text
/WEB-INF/views/home.jsp
```

---

### Error 4: CSS does not load

Check that the file is here:

```text
src/main/webapp/resources/css/styles.css
```

Also check that this line exists in `app-servlet.xml`:

```xml
<mvc:resources mapping="/resources/**" location="/resources/" />
```

And in the JSP it is written:

```jsp
<link rel="stylesheet" href="${pageContext.request.contextPath}/resources/css/styles.css">
```

---

### Error 5: Driver not found

Check that the class is in this package:

```java
package com.example.springmvcday1.controller;
```

And that the correct full path appears in the XML:

```xml
<bean id="homeController"
      class="com.example.springmvcday1.controller.HomeController" />
```

If the package or class name does not match, Spring will not be able to create the bean.

---

### Error 6: Application context mismatch

If in IntelliJ you configure the context like:

```text
/spring-mvc-day1
```

you must enter:

```text
http://localhost:8080/spring-mvc-day1/home
```

If you enter only in:

```text
http://localhost:8080/home
```

won't work, because the application context is missing.

## 19. Summary of the topic

In this first topic we have created a minimal Spring MVC application.

The main files have been:

| Archive | Function |
| --------------------- | -------------------------------------------------- |
| `pom.xml` | Configure Maven, dependencies and packaging `.war` |
| `web.xml` | Register `DispatcherServlet` |
| `app-servlet.xml` | Configure Spring MVC |
| `HomeController.java` | Respond to the request and prepare the data |
| `home.jsp` | Show the view to the user |
| `styles.css` | Add styles to the page |

The main idea is this:

```text
El usuario no abre una JSP directamente.
El usuario entra en una URL.
Spring MVC recibe esa URL.
Spring ejecuta un controlador.
El controlador prepara datos.
Spring busca una vista.
La vista genera HTML.
El navegador muestra la respuesta.
```
