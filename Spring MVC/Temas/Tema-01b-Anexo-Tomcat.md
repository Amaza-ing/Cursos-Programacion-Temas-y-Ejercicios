# Running a Spring MVC project with Tomcat in the free edition of IntelliJ

This appendix explains how to run a **classic Spring MVC** project packaged as a `.war` file using **Apache Tomcat** and the free edition of IntelliJ IDEA.

In this example we'll assume the project is called:

```text
my-project
```

Therefore, the expected final URL will be:

```text
http://localhost:8080/my-project/
```

or, if there is a controller for `/home`:

```text
http://localhost:8080/my-project/home
```

---

## 1. Prerequisites

Before we start, we need:

- IntelliJ IDEA installed.
- A Spring MVC Maven project.
- An installed JDK, for example Java 21 or Java 25.
- Apache Tomcat downloaded and unzipped.

In this course we will use Tomcat manually, because direct Tomcat integration inside IntelliJ is only available in the Ultimate edition.

---

## 2. Download and unzip Tomcat

Download Apache Tomcat from its official website:

```text
https://tomcat.apache.org/
```

For a modern project with Jakarta and a current version of Spring MVC, we will use Tomcat 11.

After downloading it, unzip the file into a simple folder, for example:

```text
C:\apache-tomcat-11
```

The structure should look like this:

```text
apache-tomcat-11
├── bin
├── conf
├── lib
├── logs
├── temp
├── webapps
└── work
```

The most important folder for us will be:

```text
apache-tomcat-11\webapps
```

That's where we will copy the `.war` file generated by Maven.

---

## 3. Check the final name of the WAR

In the `pom.xml` file, the project must use `war` packaging:

```xml
<packaging>war</packaging>
```

If we want the final file to be named exactly:

```text
my-project.war
```

we can add this block to the `pom.xml`:

```xml
<build>
    <finalName>my-project</finalName>
</build>
```

Example:

```xml
<project>
    ...

    <artifactId>my-project</artifactId>
    <packaging>war</packaging>

    ...

    <build>
        <finalName>my-project</finalName>
    </build>

</project>
```

This is important because Tomcat normally uses the name of the `.war` file as the application name.

If the file is called:

```text
my-project.war
```

the path will be:

```text
http://localhost:8080/my-project/
```

If the file is called:

```text
my-project-1.0-SNAPSHOT.war
```

the path will be:

```text
http://localhost:8080/my-project-1.0-SNAPSHOT/
```

---

## 4. Generate the WAR from the free edition of IntelliJ

Since we are not using IntelliJ Ultimate's Tomcat integration, we will generate the `.war` from the Maven panel.

In IntelliJ:

```text
View > Tool Windows > Maven
```

If the Maven panel doesn't appear, right-click the `pom.xml` file and select:

```text
Add as Maven Project
```

Then, in the Maven panel:

```text
my-project > Lifecycle
```

First, run:

```text
clean
```

and then:

```text
package
```

It may also appear as:

```text
clean package
```

When it finishes, Maven will generate a folder called:

```text
target
```

Inside it, you should see the file:

```text
target\my-project.war
```

---

## 5. Copy the WAR to Tomcat

Now copy the file:

```text
target\my-project.war
```

and paste it inside Tomcat's `webapps` folder:

```text
C:\apache-tomcat-11\webapps
```

The structure would look like this:

```text
apache-tomcat-11
└── webapps
    └── my-project.war
```

When Tomcat starts, it will automatically deploy the `.war` and create a folder:

```text
apache-tomcat-11\webapps\my-project
```

---

## 6. Start Tomcat

Open a terminal in the Tomcat root folder.

For example:

```text
C:\apache-tomcat-11
```

Run:

```bat
bin\startup.bat
```

You can also go directly into the `bin` folder and run:

```bat
startup.bat
```

If you are using PowerShell from the Tomcat root folder, you can use:

```powershell
.\bin\startup.bat
```

If all goes well, a Tomcat console window will open.

---

## 7. Open the application in the browser

Open your browser and go to:

```text
http://localhost:8080/my-project/
```

If you have a controller that responds to `/home`, go to:

```text
http://localhost:8080/my-project/home
```

For example, if you have a controller like this one:

```java
@Controller
public class HomeController {

    @GetMapping("/home")
    public String home() {
        return "home";
    }
}
```

the expected path will be:

```text
http://localhost:8080/my-project/home
```

If you also have a mapping for `/`, this will work too:

```text
http://localhost:8080/my-project/
```

---

## 8. Stop Tomcat

To stop Tomcat, run this from the root folder:

```bat
bin\shutdown.bat
```

Or from PowerShell:

```powershell
.\bin\shutdown.bat
```

You can also close the Tomcat window, although it's better to use `shutdown.bat`.

---

## 9. What to do when you change the code

If you make changes to the project, for example to:

- a Java controller,
- a JSP view,
- an XML file,
- the `pom.xml`,
- the CSS,

you have to build and deploy the `.war` again.

Recommended steps:

1. Stop Tomcat:

```bat
bin\shutdown.bat
```

2. In IntelliJ, run from Maven:

```text
clean
package
```

3. Delete the old `.war` from Tomcat:

```text
C:\apache-tomcat-11\webapps\my-project.war
```

4. Also delete the old deployed folder:

```text
C:\apache-tomcat-11\webapps\my-project
```

5. Copy the new file:

```text
target\my-project.war
```

to:

```text
C:\apache-tomcat-11\webapps
```

6. Start Tomcat again:

```bat
bin\startup.bat
```

7. Reopen:

```text
http://localhost:8080/my-project/
```

# Common errors and solutions

---

## Error 1: `mvn: command not found`

This error appears if we try to run Maven from the terminal and Maven is not installed or is not in the `PATH`.

Example of the error:

```text
bash: mvn: command not found
```

Solution for this course:

You don't need to use `mvn` from the terminal. We can use Maven directly from IntelliJ:

```text
View > Tool Windows > Maven
```

Then:

```text
Lifecycle > clean
Lifecycle > package
```

---

## Error 2: Tomcat doesn't appear in `Run > Edit Configurations`

In the free edition of IntelliJ, this option may not appear:

```text
Tomcat Server > Local
```

This is normal. Direct integration with servers like Tomcat is part of IntelliJ Ultimate.

Solution:

We will use Tomcat manually:

1. Generate the `.war` with Maven.
2. Copy the `.war` to the `webapps` folder in Tomcat.
3. Start Tomcat with `bin/startup.bat`.
4. Open the application from the browser.

---

## Error 3: The project's Java and Tomcat's Java don't match

You may get an error like this:

```text
UnsupportedClassVersionError
has been compiled by a more recent version of the Java Runtime
```

For example:

```text
HomeController has been compiled by a more recent version of the Java Runtime
class file version 69.0
this version of the Java Runtime only recognizes class file versions up to 65.0
```

This means the project was compiled with a newer version of Java than the one Tomcat is running on.

For example:

```text
Proyecto compilado con Java 25
Tomcat arrancando con Java 21
```

Solution:

You need to make Tomcat use the same Java version as the project.

### Check which JDK IntelliJ uses

In IntelliJ:

```text
File > Project Structure > Project
```

There you can see the project SDK.

You can also go to:

```text
File > Project Structure > SDKs
```

From there you can copy the JDK path.

Example path:

```text
C:\Users\tu_usuario\.jdks\openjdk-25
```

or:

```text
C:\Program Files\Java\jdk-25
```

### Configure Tomcat to use that JDK

Inside the Tomcat folder, go to:

```text
C:\apache-tomcat-11\bin
```

Create a file called:

```text
setenv.bat
```

Inside it, write:

```bat
set "JAVA_HOME=C:\Program Files\Java\jdk-25"
set "JRE_HOME=C:\Program Files\Java\jdk-25"
```

Change the path to the actual path of your JDK.

Then:

1. Stop Tomcat.
2. Start it again.
3. Redeploy the `.war`.

---

## Error 4: The application keeps showing an old version

Sometimes Tomcat keeps an older version of the project deployed.

Solution:

Before copying the new `.war`, delete:
```text
C:\apache-tomcat-11\webapps\my-project.war
```

and also:

```text
C:\apache-tomcat-11\webapps\my-project
```

Then copy the new `.war` and start Tomcat again.

---

## Error 5: HTTP 404 when opening the URL

If you see a 404 error, it could be due to several causes.

### Cause 1: The URL doesn't match the WAR name

If the file is called:

```text
my-project.war
```

the URL will be:

```text
http://localhost:8080/my-project/
```

But if the file is called:

```text
my-project-1.0-SNAPSHOT.war
```

the URL will be:

```text
http://localhost:8080/my-project-1.0-SNAPSHOT/
```

Solution:

Check the name of the `.war` inside:

```text
C:\apache-tomcat-11\webapps
```

Or add this to the `pom.xml`:

```xml
<build>
    <finalName>my-project</finalName>
</build>
```

### Cause 2: There is no controller for that path

If you go to:

```text
http://localhost:8080/my-project/home
```

there must be a controller similar to this one:

```java
@Controller
public class HomeController {

    @GetMapping("/home")
    public String home() {
        return "home";
    }
}
```

If you want to go directly to:

```text
http://localhost:8080/my-project/
```

you must also have a mapping for `/`:

```java
@GetMapping("/")
public String index() {
    return "home";
}
```

---

## Error 6: Error in the first line of a JSP

If you get an error like:

```text
page cannot be resolved to a type
pageEncoding cannot be resolved to a variable
```

check the first line of the JSP.

Incorrect:

```jsp
<% page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
```

Correct:

```jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
```

The difference is the at sign:

```jsp
<%@
```

That line is a JSP directive. Without the at sign, Tomcat tries to interpret it as Java code and fails.

---

## Error 7: The CSS doesn't load

If the JSP view opens but the CSS doesn't appear, check the static resources configuration.

In `app-servlet.xml` there should be something like:

```xml
<mvc:resources mapping="/resources/**" location="/resources/" />
```

And the CSS should be in a path like this:

```text
src/main/webapp/resources/css/styles.css
```

In the JSP, you can link it like this:

```html
<link
  rel="stylesheet"
  href="${pageContext.request.contextPath}/resources/css/styles.css"
/>
```

The expression:

```jsp
${pageContext.request.contextPath}
```

automatically adds the application's context path, for example:

```text
/my-project
```

This way we avoid writing incorrect paths.

---

## Error 8: Port 8080 is already in use

If Tomcat doesn't start because port 8080 is already in use, there may be another Tomcat or another application using that port.

Possible solutions:

1. Close the application that uses port 8080.
2. Restart Tomcat.
3. Change the Tomcat port.

To change the port, open:

```text
C:\apache-tomcat-11\conf\server.xml
```

Look for:

```xml
<Connector port="8080" protocol="HTTP/1.1"
```

and change `8080` to another port, for example:

```xml
<Connector port="8081" protocol="HTTP/1.1"
```

Then the URL would be:

```text
http://localhost:8081/my-project/
```

---

## Error 9: The WAR isn't generated

If the `target` folder doesn't appear or the `.war` isn't generated, check that the `pom.xml` has:

```xml
<packaging>war</packaging>
```

Also check that there are no compilation errors in the project.

From IntelliJ:

```text
View > Tool Windows > Maven > Lifecycle > package
```

If Maven shows errors, you have to fix them before deploying the project to Tomcat.

---

## Quick summary

Every time we want to run the project:

1. Generate the `.war` from IntelliJ:

```text
Maven > Lifecycle > clean
Maven > Lifecycle > package
```

2. Copy:

```text
target\my-project.war
```

to:

```text
C:\apache-tomcat-11\webapps
```

3. Start Tomcat:

```bat
bin\startup.bat
```

4. Open in the browser:

```text
http://localhost:8080/my-project/
```

or:

```text
http://localhost:8080/my-project/home
```

## Final note

In the free edition of IntelliJ, the process may seem more manual, but it helps you better understand how a Java web application works:

```text
Maven construye el WAR
Tomcat despliega el WAR
El navegador accede a la aplicación
Spring MVC dirige la petición al controlador
El controlador devuelve una vista JSP
```
