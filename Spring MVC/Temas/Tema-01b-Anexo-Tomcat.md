# Run a Spring MVC project with Tomcat using free IntelliJ

This annex explains how to run a **Classic Spring MVC** project packaged as an `.war` file using **Apache Tomcat** and the free version of IntelliJ IDEA.

In this example we are going to assume that the project is called:

```text
my-project
```

Therefore, the expected final URL will be:

```text
http://localhost:8080/my-project/
```

or, if a driver exists for `/home`:

```text
http://localhost:8080/my-project/home
```

---

## 1. Prerequisites

Before starting, we need to have:

- IntelliJ IDEA installed.
- A Spring MVC Maven project.
- An installed JDK, for example Java 21 or Java 25.
- Apache Tomcat downloaded and unzipped.

This course will use Tomcat manually because direct integration of Tomcat within IntelliJ is only available in the Ultimate version.

## 2. Download and unzip Tomcat

Download Apache Tomcat from its official website:

```text
https://tomcat.apache.org/
```

For a modern project with Jakarta and current Spring MVC, we will use Tomcat 11.

After downloading, unzip the file into a simple folder, for example:

```text
C:\apache-tomcat-11
```

The structure should look like this:

```text
apache-tomcat-11
├── bin
├── conf
├── lib
├── logs
├── temp
├── webapps
└── work
```

The most important folder for us will be:

```text
apache-tomcat-11\webapps
```

There we will copy the `.war` file generated by Maven.

---

## 3. Check the final name of the WAR

In the `pom.xml` file, the project must have packaging type `war`:

```xml
<packaging>war</packaging>
```

If we want the final file to be named exactly:

```text
my-project.war
```

we can add this block to the `pom.xml`:

```xml
<build>
    <finalName>my-project</finalName>
</build>
```

Example:

```xml
<project>
    ...

    <artifactId>my-project</artifactId>
    <packaging>war</packaging>

    ...

    <build>
        <finalName>my-project</finalName>
    </build>

</project>
```

This is important because Tomcat typically uses the file name `.war` as the application name.

If the file is called:

```text
my-project.war
```

the route will be:

```text
http://localhost:8080/my-project/
```

If the file is called:

```text
my-project-1.0-SNAPSHOT.war
```

the route will be:

```text
http://localhost:8080/my-project-1.0-SNAPSHOT/
```

---

## 4. Generate the WAR from free IntelliJ

Since we are not using IntelliJ Ultimate's Tomcat integration, we will generate the `.war` from the Maven dashboard.

In IntelliJ:

```text
View > Tool Windows > Maven
```

If the Maven dashboard does not appear, right-click on the `pom.xml` file and select:

```text
Add as Maven Project
```

Then, in the Maven panel:

```text
my-project > Lifecycle
```

Run first:

```text
clean
```

and then:

```text
package
```

It may also appear as:

```text
clean package
```

When finished, Maven will generate a folder called:

```text
target
```

Inside the file should appear:

```text
target\my-project.war
```

---

## 5. Copy the WAR to Tomcat

Now copy the file:

```text
target\my-project.war
```

and paste it inside Tomcat's `webapps` folder:

```text
C:\apache-tomcat-11\webapps
```

The structure would look like this:

```text
apache-tomcat-11
└── webapps
    └── my-project.war
```

When Tomcat boots, it will automatically deploy the `.war` and create a folder:

```text
apache-tomcat-11\webapps\my-project
```

---

## 6. Start Tomcat

Open a terminal in the Tomcat root folder.

For example:

```text
C:\apache-tomcat-11
```

Run:

```bat
bin\startup.bat
```

You can also go directly into the `bin` folder and execute:

```bat
startup.bat
```

If you are using PowerShell from the Tomcat root folder, you can use:

```powershell
.\bin\startup.bat
```

If all goes well, a Tomcat console window will open.

---
## 7. Open the application in the browser

Open the browser and enter:

```text
http://localhost:8080/my-project/
```

If you have a controller that responds to `/home`, go to:

```text
http://localhost:8080/my-project/home
```

For example, if you have a controller like this:

```java
@Controller
public class HomeController {

    @GetMapping("/home")
    public String home() {
        return "home";
    }
}
```

The expected route will be:

```text
http://localhost:8080/my-project/home
```

If you also have a mapping for `/`, it will also work:

```text
http://localhost:8080/my-project/
```

---

## 8. Stop Tomcat

To stop Tomcat, from the root folder run:

```bat
bin\shutdown.bat
```

Or from PowerShell:

```powershell
.\bin\shutdown.bat
```

You can also close the Tomcat window, although it is better to use `shutdown.bat`.

---

## 9. What to do when the code is changed

If you make changes to the project, for example to:

- a Java driver,
- a JSP view,
- an XML file,
- the `pom.xml`,
- the CSS,

The `.war` must be regenerated and deployed again.

Recommended steps:

1. Stop Tomcat:

```bat
bin\shutdown.bat
```

2. In IntelliJ, run from Maven:

```text
clean
package
```

3. Delete the old `.war` from Tomcat:

```text
C:\apache-tomcat-11\webapps\my-project.war
```

4. Also delete the old deployed folder:

```text
C:\apache-tomcat-11\webapps\my-project
```

5. Copy the new file:

```text
target\my-project.war
```

to:

```text
C:\apache-tomcat-11\webapps
```

6. Start Tomcat again:

```bat
bin\startup.bat
```

7. Reopen:

```text
http://localhost:8080/my-project/
```

# Common errors and solutions

---

## Error 1: `mvn: command not found`

This error appears if we try to run Maven from the terminal and Maven is not installed or is not in the `PATH`.

Error example:

```text
bash: mvn: command not found
```

Solution in this course:

There is no need to use `mvn` from the terminal. We can use Maven directly from IntelliJ:

```text
View > Tool Windows > Maven
```

After:

```text
Lifecycle > clean
Lifecycle > package
```

---

## Error 2: Tomcat does not appear in `Run > Edit Configurations`

In free IntelliJ the option may not appear:

```text
Tomcat Server > Local
```

This is normal. Direct integration with servers like Tomcat belongs to IntelliJ Ultimate.

Solution:

We will use Tomcat manually:

1. Generate the `.war` with Maven.
2. Copy the `.war` to the `webapps` folder in Tomcat.
3. Start Tomcat with `bin/startup.bat`.
4. Open the application from the browser.

---

## Error 3: Project Java and Tomcat Java do not match

You may get an error like this:

```text
UnsupportedClassVersionError
has been compiled by a more recent version of the Java Runtime
```

For example:

```text
HomeController has been compiled by a more recent version of the Java Runtime
class file version 69.0
this version of the Java Runtime only recognizes class file versions up to 65.0
```

This means that the project has been compiled with a newer version of Java than the version Tomcat is running with.

For example:

```text
Proyecto compilado con Java 25
Tomcat arrancando con Java 21
```

Solution:

Tomcat must be made to use the same version of Java as the project.

### See which JDK IntelliJ uses

In IntelliJ:

```text
File > Project Structure > Project
```

There you can see the SDK of the project.

You can also go to:

```text
File > Project Structure > SDKs
```

From there you can copy the JDK path.

Route example:

```text
C:\Users\tu_usuario\.jdks\openjdk-25
```

or:

```text
C:\Program Files\Java\jdk-25
```

### Configure Tomcat to use that JDK

Inside the Tomcat folder, go to:

```text
C:\apache-tomcat-11\bin
```

Create a file called:

```text
setenv.bat
```

Inside he writes:

```bat
set "JAVA_HOME=C:\Program Files\Java\jdk-25"
set "JRE_HOME=C:\Program Files\Java\jdk-25"
```

Change the path to the actual path of your JDK.

After:

1. For Tomcat.
2. Start it again.
3. Redeploy the `.war`.

---

## Error 4: The application keeps showing an old version

Sometimes Tomcat keeps an older version of the project deployed.

Solution:

Before copying the new `.war`, delete:
```text
C:\apache-tomcat-11\webapps\my-project.war
```

and also:

```text
C:\apache-tomcat-11\webapps\my-project
```

Then copy the new `.war` and start Tomcat again.

---

## Error 5: HTTP 404 when entering URL

If you see a 404 error, it could be due to several causes.

### Cause 1: The URL does not match the WAR name

If the file is called:

```text
my-project.war
```

the URL will be:

```text
http://localhost:8080/my-project/
```

But if the file is called:

```text
my-project-1.0-SNAPSHOT.war
```

the URL will be:

```text
http://localhost:8080/my-project-1.0-SNAPSHOT/
```

Solution:

Check the name of the `.war` inside:

```text
C:\apache-tomcat-11\webapps
```

Or add in the `pom.xml`:

```xml
<build>
    <finalName>my-project</finalName>
</build>
```

### Cause 2: There is no driver for that route

If you enter:

```text
http://localhost:8080/my-project/home
```

There should be a controller similar to this:

```java
@Controller
public class HomeController {

    @GetMapping("/home")
    public String home() {
        return "home";
    }
}
```

If you want to go directly to:

```text
http://localhost:8080/my-project/
```

you must also have a mapping for `/`:

```java
@GetMapping("/")
public String index() {
    return "home";
}
```

---

## Error 6: Error in the first line of a JSP

If you get an error like:

```text
page cannot be resolved to a type
pageEncoding cannot be resolved to a variable
```

check the first line of the JSP.

Incorrect:

```jsp
<% page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
```

Correct:

```jsp
<%@ page contentType="text/html; charset=UTF-8" pageEncoding="UTF-8" %>
```

The difference is in the symbol:

```jsp
<%@
```

That line is a JSP directive. Without the at sign, Tomcat tries to interpret it as Java code and fails.

---

## Error 7: CSS does not load

If the JSP view opens but the CSS does not appear, check your static resource settings.

In `app-servlet.xml` there should be something like:

```xml
<mvc:resources mapping="/resources/**" location="/resources/" />
```

And the CSS should be in a path like this:

```text
src/main/webapp/resources/css/styles.css
```

In the JSP, you can bind like this:

```html
<link
  rel="stylesheet"
  href="${pageContext.request.contextPath}/resources/css/styles.css"
/>
```

The expression:

```jsp
${pageContext.request.contextPath}
```

automatically adds the application context, for example:

```text
/my-project
```

This way we avoid writing incorrect routes.

---

## Error 8: Port 8080 is already busy

If Tomcat does not start because port 8080 is already in use, there may be another Tomcat or another application using that port.

Possible solutions:

1. Close the application that uses port 8080.
2. Restart Tomcat.
3. Change the Tomcat port.

To change the port, open:

```text
C:\apache-tomcat-11\conf\server.xml
```

Search:

```xml
<Connector port="8080" protocol="HTTP/1.1"
```

and change `8080` to another port, for example:

```xml
<Connector port="8081" protocol="HTTP/1.1"
```

Then the URL would be:

```text
http://localhost:8081/my-project/
```

---

## Error 9: WAR is not generated

If the `target` folder does not appear or the `.war` is not generated, check that the `pom.xml` has:

```xml
<packaging>war</packaging>
```

Also check that there are no compilation errors in the project.

From IntelliJ:

```text
View > Tool Windows > Maven > Lifecycle > package
```

If Maven shows errors, you must fix them before deploying the project to Tomcat.

```text
target\my-project.war
```

to:

```text
C:\apache-tomcat-11\webapps
```

3. Start Tomcat:

```bat
bin\startup.bat
```

4. Open in browser:

```text
http://localhost:8080/my-project/

```

```text
Maven construye el WAR

El navegador accede a la aplicación
Spring MVC dirige la petición al controlador
El controlador devuelve una vista JSP
```
